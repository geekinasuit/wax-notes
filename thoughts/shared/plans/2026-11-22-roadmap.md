# wax-notes roadmap and decision register

Status: proposed, awaiting operator review (2026-11-22). Founding input:
[`docs/design-brief.md`](../../../docs/design-brief.md), cited below as "brief §N". This plan
re-sequences the brief's §10 milestones for the build decision made on 2026-11-22 and collects
every [DECISION], [SPIKE] and [OPEN] item in one place. Update this file, not the brief, as
decisions land.

## Build strategy (D-1, D-2)

- **Bazel (bzlmod) is the build**, like the sibling geekinasuit projects (vellum, cribkeeper,
  storyteller). No Gradle.
- **Android first, then desktop JVM, then iOS.** Desktop compiles the same Compose UI against
  JetBrains' Compose Multiplatform `-desktop` artifacts (vellum's desktop tool is the precedent).
- **iOS waits for Kotlin/Native under Bazel.** rules_kotlin has no merged Kotlin/Native support
  (bazel-contrib/rules_kotlin#1682 is an open proposal; v2.4.21 notes list none). When the basic
  app works, the iOS build-out drives the operator's fork, `cgruber/rules_kotlin` (bookmark
  `kotlin_native`), with wax-notes as its consuming project (#7).
- **KMP discipline now, so iOS costs a build change and not a rewrite:**
  - Shared code lives in `shared/<module>/src/commonMain/kotlin`, tests in
    `src/commonTest/kotlin`. Today Bazel compiles commonMain as a JVM library; later the fork
    compiles the same sources for Kotlin/Native.
  - commonMain uses no `java.*`, `javax.*` or `android.*` API, including implicitly imported
    `java.lang` (`System`, `Thread`, `String.format`). A text-scan test guards this (#2).
    It is a heuristic until #7 compiles commonMain for Kotlin/Native, which is the real
    check.
  - Every library used from commonMain must publish Kotlin Multiplatform artifacts including
    iOS (kotlinx-coroutines, kotlinx-serialization, and so on). A JVM-only library may be used
    only behind a port, from `platform/`.
  - Platform capabilities (keystore, SQLite driver, WebSocket, signer intents) are interfaces in
    commonMain with implementations in `platform/<target>`, wired in `apps/<target>`. No
    `expect`/`actual` until the fork supports it (interfaces plus constructor injection cover the
    need, and are simpler).
  - Tests use `kotlin.test`, not JUnit APIs directly.
  - Shared Compose UI uses only Compose Multiplatform common APIs, no androidx-only ones.

## Proposed layout

```
docs/design-brief.md        founding design input (verbatim)
shared/                     KMP-disciplined Kotlin: commonMain + commonTest per module
  model/                    note types, ids, roles (pure)
  notes/                    note repository, domain logic
  crdt/                     CRDT port; adapter per #3's choice
  crypto/                   NIP-44, HKDF, channel-key derivation (brief §5.1)
  nostr/                    events, outer/inner layering (brief §5.2), relay client port
  sync/                     sync engine, cursors, validation (brief §4, §6.3)
  storage/                  persistence port
  ui/                       Compose Multiplatform UI (card grid, editors, share sheet)
platform/android, jvm       port implementations (ios later)
apps/android, desktop       app shells (ios later)
agent-sdk/                  Rust agent SDK + MCP tools (brief §7; milestone 5)
thoughts/shared/            plans, research, handoffs, workflows (tickets: GitHub issues)
```

Only what a ticket needs gets created; the tree above is the destination, not the first PR.

## Risks raised by the build decision

- **R-1 SQLDelight under Bazel.** Brief §2 names SQLDelight, whose code generator ships as a
  Gradle plugin. Under Bazel it needs another way to run (its compiler as a build action, or
  committed generated code), or a different SQLite layer. Settle inside milestone 1's storage
  ticket; the persistence port keeps the choice contained.
- **R-2 Kotlin version alignment.** KMP libraries (Quartz, Compose Multiplatform, CRDT bindings)
  must be readable by the kotlinc rules_kotlin bundles; vellum hit this with secp256k1-kmp.
  Each spike reports the Kotlin version its artifacts were built with.
- **R-3 Rust in the build.** A Rust CRDT core (Loro, yrs) and the Rust agent SDK (brief §7) bring
  rules_rust and the Android NDK. cribkeeper and peptide hold the org's pinned recipe; reuse it
  and move pins together.
